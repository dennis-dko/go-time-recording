# The logic-read ledger

The record kept by the logic read, step 5 of the Agentic Auditing Workflow in
`CLAUDE.md`: the files only reading can check, what only reading catches in
each, every read put to them - its commit, its date, its question and its
verdict - and how far `app.js`'s own rotation has got. The rules for reading are
in `CLAUDE.md`; this file is what they have produced.

It is kept out of `CLAUDE.md` on purpose. That file is loaded into every session
and every agent, and this record had grown to more than a third of it - a
history only a logic read needs, paid for by every task that is not one, and
rewritten by every read. So it is read when a logic read is about to choose its
file, and a read moves its row on here, in the same commit as its fix.

**Its paths start at the repository root.** The walk asks
`git log --oneline <the commit in the row>..HEAD -- <path>` of each, and git
answers a path it does not know with nothing - the same answer an unchanged file
gives. The rows used to name their files from the layer down, and on
2026-10-09 that answer for `interface/installer/installer.go` was empty while
three commits had landed on the file since its last read.
`TestTheLedgerNamesOnlyFilesThatAreThere` in `test/claims_test.go` holds every
row to it.

**Where it stands.** **10 of 10** rows stand at the bar, which is condition 1 of the target state in `CLAUDE.md`: `events.go`, `migrations.go`, `ldapsync_application_service.go`, `timesheet_application_service.go`, `installer.go`, `selfupdate.go`, `logsink.go`, `restart_handler.go`, `session_application_service.go` and `cmd/main.go`, each with two consecutive reads asking different questions that came back empty. `cmd/main.go` was the last there, at its thirteenth read of 2026-10-05.
